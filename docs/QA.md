# UI 퍼블리싱 검수

디자인 값의 정본은 [DESIGN.md](../DESIGN.md), 사용 규칙은 [TASTE.md](./TASTE.md)다. **동심성은 시스템 전체의 필수 검수 항목**이다. 색과 글꼴이 맞아도 중첩된 면의 꼭짓점과 여백이 어긋나면 통과로 보지 않는다.

## 1. 검수할 화면과 상태

- 홈, 테마의 두 미리보기, 배경 실험실, 모든 컴포넌트 문서를 확인한다.
- favicon과 OG/Twitter 공유 이미지도 현재 기본색·서체·이름 규칙과 맞는지 실제 파일을 열어 확인한다.
- 넓은 화면과 320px·390px 같은 좁은 화면, light·dark, 낮은 화면 높이를 포함한다.
- Select와 메뉴가 열린 상태, Dialog, 선택·hover·focus·disabled 상태를 확인한다.
- 전체 페이지 가로 넘침과 표·코드·탐색의 의도한 내부 스크롤을 구분한다.
- 긴 제목·설명·상태 문장이 잘리지 않고, 필요한 버튼과 키보드 focus가 화면 밖에 갇히지 않는지 확인한다.

## 2. 동심성: 필수 확인

안쪽 면이 부모의 윤곽을 일정한 간격으로 따라가는 **맞물린 모서리만** 쌍으로 측정한다. 예를 들어 이미지 카드의 위쪽 모서리, 캔버스 프레임의 모서리, 팝업 윤곽에 인접한 항목의 대응 모서리다. 부모 아래에 있다는 이유만으로 독립된 버튼·입력·대화 말풍선·중앙 썸네일의 반경을 빼지 않는다.

1. 바깥 면과 안쪽 면의 대응 모서리를 선택하고 같은 CSS px 단위로 크기·반경·간격을 측정한다.
2. 위쪽과 옆쪽 간격이 균일한지 확인한다. 선언한 padding만 보지 말고 실제 border와 wrapper 여백까지 포함한다. outline과 inset ring은 레이아웃 간격을 차지하지 않는다는 점도 구분한다.
3. 균일한 원형 코너에서는 `안쪽 반경 = max(0, 바깥 유효 반경 − 실제 간격)`이 맞는지 확인한다. 현재 기본 예는 카드 24−4=20px, 실험실 24−12=12px다.
4. 좌우 대칭, 위·옆 여백, 선택·focus 때의 선, 밝은·어두운 면에서 꼭짓점 주변 두께를 시각적으로 확인한다. 소수점 반올림을 고려한 수치 허용 오차는 0.5 CSS px다.

이 규칙은 [Apple의 concentric 모서리 설명](https://developer.apple.com/documentation/swiftui/edge/corner/style/concentric)처럼 같은 중심을 만드는 관계다. 타원 코너, 서로 다른 네 모서리, 변형된 요소는 이 단순한 균일 반경 검사로 통과시킬 수 없다. 대응 모서리별로 별도 측정·검토한다.

### 높이에 따른 반경과 과도한 라운딩

- pill 버튼은 `반경 = 짧은 변의 절반`이다. 일반적인 가로 버튼의 높이가 32/40/48px면 보이는 반경은 16/20/24px다. `rounded-full`은 이 관계를 브라우저가 크기에 맞춰 처리하게 한다.
- 일반 카드·패널은 현재 기본 바깥 반경 24px를 상한으로 출발한다. **모든 박스를 높이의 절반으로 만들지 않는다.** 큰 패널이 거대한 캡슐이 되거나 짧은 박스가 의도치 않게 pill처럼 보이지 않는지 역할에 맞춰 검토한다.
- 균일한 원형 코너는 브라우저에서 실제 짧은 변의 절반을 넘지 않도록 줄어든다. 따라서 실측 검사는 선언한 반경과 보이는 반경을 구분한다. 이 검증 명령의 유효 반경은 `min(선언 반경, 폭/2, 높이/2)`다.
- 같은 비율로 inset된 두 면에는 이 높이 보정도 양쪽에 적용한다. 예를 들어 높이 40px, 선언 반경 24px의 바깥 면은 유효 20px이며, 간격 5px·안쪽 높이 30px이면 안쪽 유효 반경은 15px다.
- 기존 승인된 독립 컨트롤 규격을 바꾸려면 역할별 기준과 검수 예외를 기록한다. 동심성을 맞춘다는 이유로 모든 자식 반경을 똑같이 만들거나 일괄 축소하지 않는다.

## 3. 실제 측정값 검증 명령

```sh
npm run check:geometry -- /absolute/path/measurements.json
```

이 명령은 **전달한 측정값을 검사한다. 브라우저를 열거나 화면을 자동 측정하지 않는다.** 실제 화면에서 얻은 데이터를 저장한 뒤 실행하고, 화면·테마·폭별로 고유한 id와 캡처를 함께 남긴다. 아래 JSON은 형식 설명이며 실행 완료의 증거가 아니다.

```json
[
  {
    "kind": "concentric",
    "id": "card-media-light-320",
    "outer": { "radius": 24, "width": 280, "height": 400 },
    "inner": { "radius": 20, "width": 272, "height": 153 },
    "inset": { "x": 4, "y": 4 }
  },
  {
    "kind": "pill",
    "id": "button-md-light-320",
    "outer": { "radius": 9999, "width": 100, "height": 40 }
  }
]
```

`radius`, `width`, `height`, `x`, `y`는 문자열이 아닌 유한한 숫자다. 크기가 0인 숨은 요소, 음수, 지원하지 않는 종류, 중복 id, 불균일한 간격, 수치가 어긋난 쌍은 실패한다. CSS에서 반경을 계산식이나 백분율로 반환하면 먼저 해당 크기에서의 숫자 값으로 해석한다. `parseFloat()`로 해석되지 않는 값을 억지로 숫자로 만들지 않는다.

명령의 종료 코드는 통과 0, 측정 실패 1, 파일·형식·사용법 오류 2다. 파일을 주지 않거나 빈 배열을 주면 실패한다. 통과 출력은 첨부한 측정값에 한정되며 모든 화면 검수를 대신하지 않는다.

검증기 자체의 경계·입력 검사는 다음으로 실행한다. 이 테스트도 브라우저 실측을 대신하지 않는다.

```sh
node --test scripts/geometry-check.test.mjs
```

## 4. 릴리스 전 기록

- 검수한 Git 상태 또는 커밋, 화면 목록, 폭·높이·테마·열린 상태를 기록한다.
- 받아들인 캡처, 실제 측정 JSON, `check:geometry` 출력과 실패 후 수정 내역을 함께 보관한다.
- 문서의 미리보기 패널도 예외가 아니다. 예제의 최대 폭을 보존하고 패널을 내용에 맞춰 감싼다. 24px 패널 안에 24px 여백으로 맞물린 블록은 0px, 여러 줄은 바깥 윤곽에 대응하는 첫 줄 위·마지막 줄 아래 코너만 보정한다. 테마 미리보기의 16px 여백에 맞물린 하단 블록은 아래 코너가 8px다. 독립 컨트롤과 중간 블록의 모서리를 일괄 덮어쓰지 않는다.
- `registry:build`, `check`, `build`, 실제 새 프로젝트 설치 검사를 통과시킨다.
- 수정 뒤에는 영향을 받는 화면과 중첩 관계를 다시 확인한다. 고정 fixture의 통과를 현재 화면의 검수 완료로 표시하지 않는다.
- 알려진 잘림·상속·동심성 문제가 남아 있으면 배포 승인 상태로 표시하지 않는다.
