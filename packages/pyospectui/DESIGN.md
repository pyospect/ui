# pyospectui 디자인 기준

2026-10-25 현재 기본값. pyospect.com의 브랜드 실험실에서 사용자가 선택한 현재 기본값을 npm 테마와 컴포넌트에 반영한다. 이 문서는 디자인 값의 정본이다. 구현은 `src/index.css`, 배포용 테마 기반은 여기에서 생성한 `packages/pyospectui/theme/base.json`이다. `docs/TASTE.md`는 이 기준을 적용하는 사용 규칙이다.

큰 화면과 작은 화면의 제목 규격은 같다. 좁은 화면에서는 좌우 여백과 열 수를 조정한다. 긴 제목과 설명은 줄바꿈을 허용한다. 말줄임은 폭이 제한된 버튼 라벨이나 보조 메타데이터처럼 한 줄이 필요한 자리에서만 사용하며, 읽어야 할 문서 제목과 본문을 자르지 않는다. 계층은 크기와 여백, 명도 차이로 만들며 글꼴 굵기를 동시에 올리지 않는다. 대문자를 나열한 장식 라벨은 사용하지 않는다.

### 밀도와 레이아웃 적용

기본 본문은 `brand-body`, 작은 설명 본문은 `brand-copy` 유틸리티를 쓴다. 카드와 대화도 이 행간과 패딩 토큰을 직접 참조한다. 토큰만 정의한 뒤 예전 `leading-5`, `p-5`로 덮어쓰면 같은 인상이 되지 않는다. `--pyo-font-mono`도 기본적으로 Pretendard sans 별칭이며 코드 예제 때문에 다른 서체를 자동으로 불러오지 않는다.

56px는 주 섹션의 위아래 여백이다. 모든 라벨, 입력창, 버튼 안에 56px를 넣는 값이 아니다. Input 높이 40px와 Button 높이 32/40/48px, 버튼의 좌우 패딩 16/20/24px는 컴팩트 컨트롤 규격으로 유지한다. 카드 내부는 24px, 카드 안 내용 사이에는 20px를 사용한다. 15px 대화 글자와 18px 대화 간격은 읽는 흐름을 위한 4px 그리드의 명시적 예외다.

브랜드 스튜디오와 UI 사이트는 같은 서체, 행간, 자간, 반경, 밀도 기준을 공유한다. 포트폴리오와 컴포넌트 문서의 정보 구조가 달라 화면 배치까지 픽셀 단위로 복제하지는 않는다. 문서의 사이드바와 미리보기, 테마 편집기의 도구 영역은 각각 콘텐츠가 잘리지 않는 반응형 배치를 사용한다.

### 동심형 모서리 규칙

코너를 통일한다는 말은 중첩된 모든 면에 같은 24px를 주는 뜻이 아니다. 안쪽 면이 바깥 컨테이너의 윤곽을 일정한 간격으로 따라갈 때는 같은 중심을 갖는 동심형 모서리(concentricity)를 쓴다. 균일한 간격에서는 `안쪽 반경 = max(0px, 바깥 반경 - 간격)`으로 계산한다. 이 관계는 [Apple의 concentric 모서리 설명](https://developer.apple.com/documentation/swiftui/edge/corner/style/concentric)과 같은 기하 원리다.

| 중첩 관계 | 바깥 반경 | 간격 | 안쪽 반경 |
|---|---|---|---|
| 미디어 카드와 이미지 | 24px | 4px | 20px |
| 실험실 카드와 캔버스 | 24px | 12px | 12px |
| 목록 또는 Select 팝업과 안쪽 행 | 24px | 4px | 20px |

패널 속에 있다는 이유만으로 모든 자식의 반경을 빼지는 않는다. 입력창, 버튼, 중앙에 독립적으로 놓인 썸네일처럼 부모 윤곽을 따라 맞물리지 않는 요소는 자기 역할의 24px 또는 pill 규격을 유지한다. 간격이 반경보다 크면 안쪽 반경은 0이다. 배치는 같은 중심을 만들기 위한 실제 간격을 쓰고 임의의 중간 반경을 고르지 않는다.

동심성은 [필수 검수 항목](https://github.com/pyospect/ui/blob/main/docs/QA.md)이다. pill 버튼은 높이 32/40/48px에서 실제 반경 16/20/24px를 갖지만, 모든 일반 박스를 높이의 절반으로 둥글게 만들지는 않는다. 일반 면은 현재 기본 상한 24px와 역할을 유지하고 과도한 캡슐 모양을 검토한다. 실제로 짧은 박스에서는 CSS가 반경을 폭·높이의 절반 이하로 줄이므로 바깥과 안쪽의 **유효 반경**을 비교한다. 브라우저 측정 JSON을 `npm run check:geometry -- <파일>`로 검사하며, 수치 확인과 화면의 꼭짓점·균일한 여백 확인을 함께 통과해야 한다.

### 테마를 따르는 선택 목록

기본 선택 UI는 `Select`, `SelectTrigger`, `SelectValue`, `SelectContent`, `SelectItem`을 조합한다. 트리거뿐 아니라 열린 팝업과 선택, 포커스, 비활성 상태까지 pyospect의 역할 토큰을 사용한다. 기본 바깥 반경은 24px이며 팝업의 4px 안쪽 행은 20px다. 트리거의 쉐브론은 16px, 오른쪽 12px, 수직 중앙이다.

운영체제가 그리는 native select 메뉴는 브라우저마다 모양과 테마 제어 범위가 달라 같은 팝업 디자인을 보장하지 않는다. 테마 일치가 필요한 제품 선택기는 이 Select 컴포넌트를 쓴다. 방향키, Enter, Escape, 비활성 항목과 닫힌 뒤 포커스 복귀를 유지한다. 페이지 일부만 다른 테마로 감싼 경우에는 SelectContent의 `container`로 팝업이 같은 테마 범위에 놓이게 한다.

## 색과 다크모드

| 역할 | light | dark |
|---|---|---|
| 페이지 bg | #fafafa | #0a0a0a |
| 카드 surface | #ffffff | #171717 |
| 보조 surface-2 | #f5f5f5 | #262626 |
| surface-3 | #e5e5e5 | #404040 |
| 제목 text | #262626 | #f5f5f5 |
| 본문 text-2 | #525252 | #d4d4d4 |
| 도움말 text-3 | #606060 | #a3a3a3 |
| primary brand | #171717 | #f5f5f5 |
| primary 위 글자 | #fafafa | #171717 |
| border / input | rgba(0,0,0,.1) | rgba(255,255,255,.1) |

UI의 기본 면에는 초록색 등 유채색 기운을 넣지 않는다. artwork, 포트폴리오 이미지, 배경 실험실의 색상은 그대로 유지한다. 다크모드 때문에 이미지에 invert, grayscale 필터를 적용하지 않는다. `html.dark` 또는 테마 범위의 `.dark`로 전환한다. light가 기본이고 사용자 설정은 로컬에 보관한다.

일반 경계선은 낮은 농도로 두되, focus ring은 2px과 offset 2px로 분명하게 표시한다. 스위치 off 트랙처럼 상태를 읽는 데 필요한 선에는 별도의 `line` 토큰을 쓴다. `line`은 light #767676, dark #8a8a8a이며 면과 3:1 이상을 검사한다. 장식 border와 의미 있는 상태선을 같은 대비 기준으로 처리하지 않는다. 본문과 채움 위 글자는 4.5:1 이상을 검사한다.

## 기본 테마와 선택 프리셋

`pyospect` 프리셋은 `#171717`에서 시작하는 neutral 테마다. 다크모드에서는 primary를 밝은 neutral로 전환한다. 색조가 있는 프리셋과 `--brand` 입력은 기존 OKLCH 생성 규칙을 유지한다. 채도가 낮은 사용자 지정 색은 기본 neutral seed #171717을 제외하면 받지 않는다. 브랜드를 바꾸어도 글꼴, 공통 반경, 여백, neutral 면은 바뀌지 않는다.

현재 코드 변경은 다음 npm 배포를 위한 소스 변경이다. 이미 배포된 npm 버전과 호스팅 사이트의 기본값이 자동으로 바뀌지는 않는다. 버전 변경과 npm publish, 사이트 배포는 별도의 릴리스 작업이다.

## 배경 실험실

흐린 색면, 번짐, 그레인과 섬유 질감을 Canvas로 생성한다. 기존 기본 이미지의 seed, 팔레트, blur, warp, grain, texture는 유지한다. 효과는 이미지 위에 CSS 필터를 씌우지 않고 렌더러에 전달한다. UI는 neutral을 유지하고 그림 안의 색상만 다양하게 쓴다.

팔레트의 색조뿐 아니라 명도와 채도도 바꿀 수 있게 자연스러운 기본값, 파스텔, 선명한 톤, 저채도, 딥 톤을 제공한다. 현재 작업, 저장한 시안, JSON 교환과 PNG 내보내기를 지원한다. 저장 데이터는 로컬 브라우저에 보관하며 서버나 모델 API를 호출하지 않는다. PNG에는 배경 그림만 들어가고 조작 UI나 로고는 들어가지 않는다.

### 설치와 API

```bash
npx pyospectui wash-lab
```

```tsx
import { WashLab } from "@/components/ui/wash-lab"

export default function Backgrounds() {
  return <WashLab />
}
```

데모 사이트의 `#/lab`에서 같은 컴포넌트를 확인한다. 렌더러만 쓰려면 `@/lib/wash-engine/engine`의 `renderWash`를 가져온다. 시안 JSON은 원본 색과 색감 변주를 보관하고, 엔진 옵션과 PNG는 변주가 적용된 색으로 내보낸다.

## 적용과 검증

1. `src/index.css`를 바꾼 뒤 `npm run registry:build`로 레지스트리, base.json, 프리셋 문서를 다시 생성한다.
2. `npm run check`로 기본 테마와 프리셋 대비, 고정 토큰 동기화, 컴포넌트 사용 규칙을 검사한다.
3. `npm run build`와 로컬 설치 검사를 통과시킨다.
4. 밝은 화면과 다크 화면, 좁은 화면에서 제목, 본문, 드롭다운, 말풍선, 키보드 focus를 확인한다.

shadcn 기본 컴포넌트는 테마 색과 토큰을 받아도 버튼 모양, 그림자, 배지 반경 같은 자체 스타일이 남을 수 있다. pyospectui 컴포넌트를 쓰거나 이 문서의 모양 규칙까지 맞춘다. preset bbVKFP6는 출발점이었으며 현재 문서에 기록한 사용자 선택값이 우선한다.
